# Profession-Archives

![logo](logo.png)

## 产品定位

**本地优先的个人生涯大脑 + 求职面试全生命周期管理平台**：沉淀你一生的原子化经历，生成个人名片与特化简历；从投递、面试到复盘、补足短板的每一个环节都被记录、被分析、被 AI 辅助，最终形成一个不断进化的职业成长闭环。

## 背景

本项目从一期"简历管理工具"升级而来。一期已落地：本地优先的档案原子化管理（[db.py](backend/app/db.py)）、岗位投递看板（[TrackingBoardView.vue](frontend/src/views/TrackingBoardView.vue)）、JD 关键词匹配简历草稿（[resume_builder.py](backend/app/services/resume_builder.py)）。

升级的核心驱动是一个明确的痛点：**部分岗位的简历投递入口在招聘公司官网（或第三方平台的官网页面）的表单里**，本文档规划了"本地化软件 + 浏览器插件"的配合方案——读取官网简历提交页面、自动填充、用户确认后提交。

三个已确认的产品决策：

| 决策点         | 结论                                                                         |
| -------------- | ---------------------------------------------------------------------------- |
| 自动投简历交互 | **插件填充 + 人工确认提交**（不绕过验证码/登录，不搞反爬对抗）               |
| AI 能力来源    | **可配置双模式**：默认云端 DeepSeek（Anthropic 兼容网关），可切换本地 Ollama |
| 需求文档落盘   | 本文档（README.md）即完整 PRD                                                |

## 产品愿景

- **长期主义**：不是"求职季用一下就扔"的工具，而是持续记录、持续复利的个人职业资产库。
- **个人名片**：把简历变成"活的"——由原子化记录实时生成，而非一次性编辑的静态文档。
- **求职全生命周期**：一个岗位从发现 → JD 分析 → 特化简历 → 投递 → 每一轮面试 → 复盘 → 转化分析 → 短板补足的完整闭环。
- **自动化**：能自动化的尽量自动化（尤其官网表单投递），但保留人工最终控制权。
- **AI 辅助而非取代**：AI 负责总结、润色、复盘、建议；决策永远在人。

## 目标用户

- **学生求职者**：从校园到职场的第一次求职，记录实习、竞赛、项目经历，系统化准备简历与面试，赢在起跑线。
- **中年奋斗的职场人士**：长期经营职业、积累复利，从容应对转岗、晋升、跳槽等关键节点，把每一次求职都变成成长机会。

## 核心设计理念

| 理念     | 含义                                                            |
| -------- | --------------------------------------------------------------- |
| 本地优先 | 数据全部存本地 SQLite，无云同步强制依赖；可导出、可备份         |
| 隐私可控 | AI 云端调用需明确授权，可一键关闭出境；插件只拿最小权限         |
| 原子化   | 一切素材拆成最小颗粒记录（日记、成就、项目、技能…），可任意重组 |
| 闭环     | 每一次投递与面试的反馈都回流，驱动下一次行动                    |

## 核心使用场景（用户旅程）

### 通用闭环：一个岗位从发现到成长的完整旅程

1. **随手记录**：每天/每周把工作进展、成就、灵感记成原子条目（支持 Markdown、标签、附件）。这是 AI 提炼和简历素材的原料。
2. **发现与采集岗位**：看到合适岗位 → 粘贴岗位 URL 直采，或直接在当前页面点插件"采集岗位"（自动抓取公司、JD、快照入库看板）；对需登录的招聘网站，插件天然复用浏览器登录态，无需导出 cookie。
3. **生成特化简历**：AI 分析 JD → 生成特化简历草稿 → 润色后导出 PDF。
4. **投递并追踪**：打开官网投递页 → 插件读取档案自动填充表单 → 人工确认提交 → 投递结果自动回传看板"已投"，状态随后续每一轮面试流转。
5. **面试与复盘**：每面结束记录（形式、面试官、题目、回答、自评、结果）→ 投递状态自动推进 → AI 生成复盘要点并沉淀为面经。
6. **自我提升**：月度复盘查看转化漏斗与失败原因分布 → AI 分析能力短板 → 生成学习计划 → 学习成果回流入档案，形成成长闭环。
7. **经营个人名片**：把档案编排成对外可展示的个人名片页（或链接），像程序员的 Blog/个人主页一样呈现你想展示的经历与项目，可附在简历中对外分享，持续积累个人品牌。

### 差异化场景

- **学生求职者**：从校园到职场——记录实习、竞赛、课程项目 → AI 提炼成简历亮点 → 生成第一份简历并模拟面试准备 → 拿到首个 offer 后继续沉淀校园与职场经历。
- **中年奋斗的职场人士**：职业长期经营——跳槽/转岗前系统盘点多年经历 → 分析能力缺口与市场定位 → 定向补足短板 → 把每一次面试反馈沉淀为长期职业资产，从容应对关键节点。

## 功能需求详述

### 模块 A：生涯档案与个人名片

> 现状：已有 profiles / skills / experiences / education / projects 五类原子表 + 档案录入/管理视图（[ArchiveEntryView.vue](frontend/src/views/ArchiveEntryView.vue)、[ProfileManagerView.vue](frontend/src/views/ProfileManagerView.vue)）。

- **A1 原子化记录（P0）**：在现有五类基础上新增 `日记 / 成就 / 里程碑` 类目；每条记录含类型、时间、标签、Markdown 正文、附件列表。
- **A2 聚合名片（P0）**：按时间线 / 类型 / 标签聚合所有记录，生成可展示的个人名片视图与实时简历素材库。
- **A3 AI 提炼（P1）**：选中多条零散记录（如一周日记），AI 提炼成一条简历可用的结构化亮点；提炼结果可一键存为"成就"。
- **A4 生涯时间线（P2）**：可视化整段职业经历的时间轴视图。
- **A5 对外名片展示（P1）**：提供一个可对外展示的个人名片功能/链接，将用户想展示的档案内容（经历、项目、技能等）呈现为个人主页风格的名片页，可附在简历中分享；具体展示形式后续细化。

### 模块 B：求职与投递管理

- **B1 投递看板增强（P0）**：在现有看板基础上扩展状态机：`备选 → 已投 → 简历被读 → 一面 → 二面 → 终面 → Offer / 拒绝 / 放弃`，支持自定义标签与备注。
- **B2 岗位采集（P0）**：JD 全文、岗位 URL、页面快照（现有 `snapshot_path` 字段）完整保留，作为 AI 分析与复盘依据。支持三种采集入口：
  - **URL 直采**：在看板直接粘贴岗位 URL，本地服务抓取并解析标题、公司、JD。
  - **插件采集（推荐）**：在已登录的招聘网站/官网岗位页点击插件"采集岗位"，从当前页面提取岗位信息回传入库，天然复用浏览器登录态。
  - **Cookie 补充**：对需登录态的招聘网站，可接入浏览器导出的 cookie 供本地抓取；cookie 敏感、易过期，定位为补充能力（详见插件设计要点）。
- **B3 特化简历生成（P0）**：现有 JD 关键词匹配草稿保留并增强：多套模板、AI 润色、导出 **PDF / Word**。
- **B4 投递统计（P1）**：渠道 / 岗位 / 时间维度的投递与转化统计。

### 模块 C：面试全流程管理与复盘

- **C1 面试记录（P0）**：每个投递可挂多轮面试，每轮记录：时间、形式（电话/视频/现场）、面试官、题目、我的回答、自评、结果（通过/待定/淘汰）。
- **C2 状态流转（P0）**：每记录一轮结果，投递看板状态自动推进。
- **C3 面试复盘（P1）**：AI 基于一轮或多轮记录生成复盘要点（做得好 / 待改进 / 下次策略），沉淀为可检索的面经。
- **C4 面经题库（P1）**：题目按标签归类，形成个人题库，复盘时按薄弱方向优先复习。

### 模块 D：自动化投简历（本地软件 + 浏览器插件）★ 核心痛点

> 目标场景：部分岗位的投递入口是公司官网（或第三方平台的官网页面）的简历提交表单，不是标准 ATS 或邮箱投递。用本地软件 + 浏览器插件配合，把表单自动填好，用户确认后提交。

- **D1 本地桥服务（P0）**：桌面端暴露一个仅绑定 `127.0.0.1` 的本地 HTTP 服务，双向通信——供插件读取"当前要投递的档案"（姓名、邮箱、电话、职位经历、简历附件等），也接收插件采集的岗位信息与投递结果回传。
- **D2 浏览器插件（P0，统一入口）**：Manifest V3 扩展（Chrome / Edge），一个插件同时承担**岗位采集**与**表单投递**：
  - **采集动作**：在岗位详情页点击"采集岗位"，从当前 DOM 提取公司、岗位、JD、URL、页面快照并回传本地服务，自动在看板创建记录。
  - **投递动作**：在官网投递页点击"填充表单"，读取档案自动填充，人工确认后提交。
- **D3 表单识别（P0）**：扫描当前页面的 form / input / select / textarea / file 控件，用字段名 / id / label 启发式识别常见字段。
- **D4 字段映射（P0）**：内置常见字段映射规则；识别不准确时用户手动指定，映射按站点（origin）持久化记忆，下次同站自动复用。
- **D5 填充 + 人工确认（P0）**：自动填充后高亮所有已填控件，用户检查并点击"确认提交"；支持先只填不提交（预览）。
- **D6 简历附件上传（P1）**：从本地档案选择一份 PDF 简历，填充到表单的 file 控件（必要时提示用户手动选文件）。
- **D7 投递回传（P1）**：提交成功后，把岗位 / 公司 / 页面 URL 回传到桌面端，自动在看板创建/更新"已投"记录。
- **合规边界（P0 硬约束）**：不破解验证码、不绕过登录、不做反爬对抗；一切提交动作必须有用户主动确认。

### 模块 E：AI 辅助能力（可配置双模式）

- **E1 双模式配置（P0）**：设置页选择模型来源——**云端**（DeepSeek，Anthropic 兼容网关，默认）或**本地**（Ollama）；Endpoint / API Key / 模型名可配置。
- **E2 能力清单（P1）**：
  - 素材提炼（模块 A3）
  - 简历润色：对草稿逐段优化措辞、强化 JD 关键词
  - JD 语义匹配：超越现状的关键词打分，生成定制化个人 summary
  - 面试复盘（模块 C3）
  - 学习计划（模块 F2）
- **E3 隐私提示（P0）**：首次调用云端 AI 前明确提示数据出境，提供全局"仅用本地模型"开关。

### 模块 F：成长闭环（自动分析路线 + 补足短板）

- **F1 路线自动分析（P1）**：统计各环节转化率（投递→简历被读→一面→…→Offer）、失败原因分布（拒绝原因打标签），用图表呈现"死在哪个环节"。
- **F2 短板补足（P2）**：AI 结合失败原因与能力标签，生成个人能力差距分析与学习计划；计划回流入档案作为待办。
- **F3 提升追踪（P2）**：技能熟练度随时间演化，与学习计划联动。

## 浏览器插件设计要点（模块 D 细化）

```
┌─────────────────────────┐        localhost HTTP        ┌──────────────────────┐
│  浏览器插件 (MV3)         │ ◄──────────────────────────► │  桌面端本地服务         │
│  content script 扫表单    │    GET /api/automation/      │  FastAPI + SQLite      │
│  popup 面板 + 确认按钮     │    profile?token=xxx         │  (仅绑定 127.0.0.1)     │
└─────────────────────────┘                               └──────────────────────┘
```

- **通信安全**：桌面端本地服务带一次性**配对 token**（首次在插件面板粘贴桌面端生成的配对码）；CORS 白名单仅放行扩展 origin。
- **表单识别策略**：先静态启发式（name/id/label 关键词表），命中率不足时用户在 popup 手动指定字段并记忆；对 React/Vue 动态渲染页面，等待表单稳定后再注入。
- **字段映射存储**：per-origin 配置存插件 storage（或桌面端），跨会话复用。
- **登录态策略**：插件天然复用浏览器已登录会话——招聘网站（BOSS 直聘、拉勾、猎聘等）的 cookie 由浏览器持有，无需导出到本地，隐私更安全；仅当希望"脱离浏览器"采集时才手动接入 cookie（本地需加密存储，且 cookie 易过期，定位为补充能力）。
- **支持的浏览器**：Chrome / Edge（MV3）优先；Firefox 后续。

## 验收标准（每模块可验收的最小标准）

- **A**：能新增日记/成就类原子记录，并在档案聚合视图看到；AI 能把 3 条日记提炼成 1 条可用简历素材。
- **B**：投递看板支持完整状态机流转；任一档案 + JD 能生成特化草稿并导出 PDF。
- **C**：一个投递下能记多轮面试；每轮结果自动推进看板状态；AI 能产出该投递的复盘要点。
- **D（核心）**：在招聘网站岗位页点插件能采集岗位并入库看板；对至少 1 个真实官网投递表单，插件能识别并填充姓名/邮箱/电话等字段，用户确认后提交成功；再次访问同站自动复用映射。
- **E**：设置页可切换云端/本地模型并生效；首次云端调用出现授权提示。
- **F**：能查看投递→面试的转化漏斗与失败原因分布；AI 能产出短板分析报告。

## 风险与开放问题

1. **官网表单千差万别**：字段识别准确率不可能 100%，必须靠"人工纠正 + 逐站记忆"兜底，MVP 只承诺对常见表单可用。
2. **动态渲染 / 校验**：React/Vue 页面需等待渲染稳定；必填校验、文件上传格式校验可能导致填充失败，需用户介入。
3. **反爬合规**：明确不做对抗性操作；仅对公开静态表单自动化，遇到验证码/登录即停。
4. **AI 隐私**：云端调用涉及简历数据出境，授权提示与全局开关必须在 M1 落地。
5. **数据迁移**：现有 SQLite 库（`.profession_archives/profession_archives.sqlite3`）需加迁移逻辑，不丢已有数据。

## 扩展方向与行业规划

### 行业定位策略

- **起步：计算机/互联网行业**——内容质量有保障，能快速打磨出可用闭环。
- **架构：行业无关 + 可插拔行业包**——元模型与具体行业解耦，内容按行业分类。
- **未来：扩展到更多行业**——产品、设计、运营、金融、医疗等，通过"新增行业包 + 灌内容"实现，而非推倒重来。

核心原则：**元模型行业无关，内容按行业分类**。档案、证书、题库、技能全部带 `industry` / `category` 标签。

### 相邻需求（第一梯队，建议纳入路线图）

1. **证书 / 资质管理**：行业通用资质证书管理，有效期 + 继续教育提醒，链上存证（有编号与颁发机构，存证可信度最高）。未来行业包扩展后即为律师执业证 / 医师资格 / 金融从业资格等。
2. **薪资 / Offer 对比与跳槽分析**：记录 Offer 条件，AI 横向对比与跳槽成本收益评估，辅助求职决策。
3. **学习与技能成长追踪**：从"补短板"升级为终身学习库——技能熟练度演化、学习计划、成果回流。

### 相邻需求（第二梯队，远期储备）

4. **人脉 / 内推关系管理**：记录面试官、同事、可内推的人脉与维护提醒，覆盖求职隐性渠道。
5. **垂直面试题库**：先做计算机行业通用题库（后端 / 前端 / 算法 / 数据 / 系统设计等方向），行业包机制成熟后再扩展。

### 架构启示（行业可插拔）

- 数据表（证书、题库、技能等）自第一天起带 `industry` / `category` 字段。
- 名片页展示、AI 提炼 prompt、简历模板均按行业参数化。
- 扩展到更多行业 = 加行业包 + 灌内容，而非重构数据模型。

## 运行

下载 release，即可启动应用。开发模式：

- 后端：`uvicorn backend.app.main:app`（源码运行时数据落在 `.profession_archives/`）
- 前端：`cd frontend && npm install && npm run dev`（Vite dev 端口 5173，走 `/api` 代理）
- 桌面：`python backend/desktop.py`（PyWebView 窗口 + 本地 FastAPI）
